## 新增产物:tools/publish-release-direct.ps1(标准件)

零参数、AI 打包后复制到 `temp/<slug>/<v>/publish-release.ps1` 与 zip 同目录:

1. **自动推导**:`$Tag`=所在目录名(v0.x.y)、`$Slug`=上一级目录名、`$ZipPath`=同目录唯一 `*.zip`
2. 打印 slug/tag/zip/大小 → 输入 y 轻量确认(防手滑)
3. 委托核心脚本 `tools/publish-demo-release.ps1` 执行 `gh release create`
4. 发布成功询问是否 `git push origin main`,输入 y 一步触发 Pages 部署

safety:gh 未装/未认证/无 zip/多 zip 均 `[ERR]` 退出;副本被 .gitignore 排除不入库。

## 设计决策

- **标准件在 tools/(入库)、副本 cp 到 temp/<slug>/<v>/(被忽略)**——不散乱维护
- **repoRoot 用向上 walk 探测**(找 tools/publish-demo-release.ps1),不硬编码层数,
  脚本位置无关,从 temp/ 或别处都能命中
- **用户可见字符串全英文**(中文只放 # 注释)——绕开 PowerShell 5.1 parser 坑
- **确认环节保留 + 发布后问 git push**(用户选的推荐项)

# 2026-09-08(三)· release tag 加 slug 前缀

会撞 tag(GitHub Release tag 是仓库级唯一命名空间)。

## 方案

- **release tag 改为 `<slug>-v<version>`**,如 `HanmoWesnoth-v0.1.0`,不同产品版本号可自由重复
- 目录名仍用纯版本 `v0.1.0`(temp/<slug>/<version>/),tag 由 slug+version 拼出
- asset URL 随 tag 唯一:`.../releases/download/HanmoWesnoth-v0.1.0/HanmoWesnoth-v0.1.0-win.zip`
