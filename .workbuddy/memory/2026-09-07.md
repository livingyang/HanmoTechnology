## 发布频率问询（18:27，用户问"每个 zip 包都需要手动发布吗"）

**回答**：当前架构下，是的，每个 zip 都要用户手动发布。

**三条沙箱限制**：
1. `gh` CLI 不可用（PATH 没 + 实测失败）
2. 用户没给我 GitHub token
3. HTTPS 被 TLS 中间人阻断，curl/Invoke-RestMethod 直连 github.com 不稳

**四条出路对比**：
| 方案 | 配置 | 每次发布成本 | 适合场景 |
|---|---|---|---|
| A 浏览器拖拽 | 0 | 60-90s | demo 阶段（当前） |
| B 本地 `gh` CLI | `winget install GitHub.cli` + `gh auth login` 一次 | 10s | 长期 / 高频 |
| C PowerShell + PAT | classic PAT with `repo` scope | 30s | 没 admin 装不了 `gh` |
| D Actions 自动 | 违背 v4.0"去 Actions"原则 | — | 否决 |

**我的判断**：demo 阶段 × 1 平台 × 一年 5-15 次发布，手动 60-90s 完全够，
**轻量优于重**。等 demo 转周更/日更频率再上 `gh` CLI。

### 上传 release 归属

### 设计
- 复用 `gh auth` 凭据（OAuth 或 PAT），脚本不接触明文 token
- 三个必填参数：`-Tag` / `-ZipPath` / `-Slug`
- 三种 mode：默认 PUBLIC（加 y 确认）、`-Draft`（不公开）、`-Replace`（先删后建）
- 跑成功自动打印可直接复制的 JSON 片段（manifest + products.json downloads[]）

### PowerShell 5.1 parser 坑（**这是一个完整的踩坑记录**）
症状：PowerShell parser token 化时报大量 cascade 错（line X expression contains
unexpected token Y）—— 实际错误指向位置常严重错位（甚至错位 20 行+）。

最小复现：
```powershell
$x = 'DRAFT（不公开）'  # OK
$y = 'PUBLIC（立即公开）'  # line Y 报"unexpected PUBLIC..."
```
**line 2 错，line 1 不错**——奇怪的不对称。

诊断：PowerShell 5.1 parser 对 UTF-8 BOM-less 文件里【中文字符 + ASCII 字符相邻】有
token 化 bug；行尾中文标点（`。`、`，`、`？）`、`：`、`；`等）和双引号字符串里
的中文括号都触发 cascade。

**绕开策略**（已应用在本脚本）：
1. 用户可见字符串一律 **英文**（含 [ERR] / [info] / [ok] 标签）
2. 中文只放 **# 行注释**里，不放 string / expression
3. 不要 `<#..#>` block comment 里放 `` ` `` 反引号 或 `--` 多连字符
4. 避免 `Write-Host ("a" + $var)` 这种 + 拼接写法；用直接插值 `"a $var"`
5. PowerShell 5.1 + 中文 = 必踩坑；PowerShell 7 (pwsh) 大概率修好了

**诊断工具**：
```powershell
$tokens=$null; $errs=$null; $null=[System.Management.Automation.Language.Parser]::ParseFile('x.ps1',[ref]$tokens,[ref]$errs)
$errs | ForEach-Object { "[ERR] line $($_.Extent.StartLineNumber): $($_.Message)" }
```
